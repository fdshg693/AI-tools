# tav: `pages/` を `aim --parallel` で並列抽出する

`--topic` 付きの `extract` / `crawl` / `search-extract` / `map-extract` で集めた `pages/` を、1件ずつ Read する代わりに `aim --parallel` で並列にAI抽出し、関連する内容だけを報告させる手順。

前提: `aim` コマンドが PATH 上で使え、`OPENROUTER_API_KEY` が設定済み。`aim` の使い方・モデル選択・失敗時の挙動は `aim-cli` スキル(`tools/_plugin/my-tools/skills/aim-cli/SKILL.md`)を参照する。

## 使うとき・使わないとき

判断は必ず `pages/index.json` を Read した後に行う(`tav` 実行直後に返るのは stderr の「Wrote ... .md file(s) to ...」通知のみで、集計値は返らない)。

| 状況                                                                     | やること                                  |
| ------------------------------------------------------------------------ | ----------------------------------------- |
| `pages/` の件数が1〜2件で、内容もすぐ読める規模                          | そのまま Read(この手順は使わない)         |
| `index.json` でタイトルから選んだファイルが小さい(`char_count` が少ない) | そのまま個別に Read                       |
| `pages/` の件数が多くタイトルだけでは関連性を判断しづらい(目安5件以上)   | この手順で全件投入                        |
| `index.json` で選んだファイルの中に `char_count` が大きいものが複数ある  | この手順で選んだ分だけ投入                |
| 1ファイルだけを抽出したい                                                | `aim-cli` を直接使う                      |
| discovery(`search/`・`map/`)や report(`research/`)を読みたいだけ         | そのまま Read(集約1ファイル/単一レポート) |

「大きい」の閾値は会話の残りコンテキスト量や個別ファイルの内容次第で変わるため固定値はなく、各エントリの `char_count` を見て都度判断する。

## 手順

```markdown
1. `pages/index.json` を Read し、entries(file・url・title・title_source・char_count)
   一覧から aim に渡す対象を決める(上表)

2. 元の質問/知りたいことを1本の「抽出プロンプト」に言語化する(下記)。ファイルごとに
   指示を変える必要は通常ないので、同じ抽出文を各 `--prompt` に繰り返す。ファイル名や
   個々のタイトルはプロンプトに埋め込まない

3. 本実行の前に、選んだファイルのうち1件だけを
   `aim --prompt "<抽出プロンプト> @<1件のパス>"` で投げ、エラーなく応答が返ることを
   確認する(モデル側の問題を全件投入前に切り分けるため)

4. 選んだエントリの `file` を `pages/` と結合したパスを、ファイルごとに1つの
   `--prompt` として"まとめて1回" aim に渡す
   aim --parallel --jobs <並列数> --prompt "<抽出プロンプト> @<topic_dir>/pages/0001-....md" "<抽出プロンプト> @<topic_dir>/pages/0002-....md" ...
   → ファイルごとの応答が返る。Claude 自身が個別ファイルを Read する必要はない

5. 「関連なし」以外の項目だけをユーザーへの回答に統合する。出典URLは、aim の応答が
   返す `file` パス(または `path`)を `pages/index.json` の `file` と突き合わせて
   `url` を引く(ページ本文は `# title` + 本文のみで URL 行を持たないため、
   プロンプトで URL の転記は指示しない)

6. 抜粋だけでは情報不足な場合だけ、`pages/index.json` の `url` を `tav extract` で
   再取得する(`--query` なしでの全文取得、`--detail max` など)か、同じ要領で
   aim(1ファイルのみでも可)に該当箇所を抽出させる
```

## 抽出プロンプトの作り方

「何を探しているか」をファイル非依存の形で言語化し、指示と対象 `@path` を1プロンプトにまとめて、ファイルの数だけ並べる。

例: ユーザーの質問が「Microsoft Fabric の OneLake と Lakehouse の違い」の場合

```text
以下はWeb調査で取得したページ本文の抜粋です。
「Microsoft Fabric の OneLake と Lakehouse の違い」に関連する記述があれば、
該当箇所を日本語で簡潔に抜き出してください。
関連する記述が無ければ、他には何も書かず「関連なし」とだけ答えてください。
```

- ❌ 単に「要約してください」だけだと、無関係な結果まで律儀に要約されてフィルタリングにならない。**「関連が無ければ関連なしとだけ答える」を必ず明示する**
- 抜粋が途中で切れている(`--query` 付き抽出時のチャンク境界 `[...]` など)兆候を拾いたい場合は、「情報が不十分そうなら『要フルページ再取得』と付記して」も足すと、手順6に進むべきファイルを aim の応答だけから判断できる

## 並列数(`--jobs`)の目安

- 既定 `--jobs 4` でも十分速いが、件数が多い/急ぎなら `--jobs 8`〜`10`(上限)まで上げてよい。`--jobs` は `--parallel` 専用
- 同じ `--topic` に複数回 `extract` / `crawl` して `pages/` が積み上がっている場合も、選んだ全ファイルを1回の `aim --parallel` に並べれば同様に並列化される
- `--jobs` を上げても速くなるのは AI 呼び出しが正常に進む場合のみ。まず手順3の1件スモークテストで切り分ける

## 注意点

- `aim --parallel` はステートレスで永続化しない。同じトピックを再処理する場合は都度呼び直す(`pages/` 配下のファイル自体はトピックフォルダに残るため再利用できる)
- 個別ファイルの読み込み失敗・AI呼び出し失敗は、そのプロンプトだけ失敗として記録され他ファイルの処理は継続する。失敗したファイルは `tav extract` など代替手段で個別に読む
- **全ファイルが同一のエラーメッセージで失敗した場合は、モデル/API側の問題を疑う**(例: 既定の無料枠モデルが提供停止で全滅する)。この場合は手順6の個別フォールバックに進んでも無意味なので、`--model` に別のモデル略記(`aim --list-models` 参照)を明示して全件を再実行する
