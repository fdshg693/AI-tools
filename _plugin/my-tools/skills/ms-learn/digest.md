# mslearn: 結果ファイルを `aim --parallel` で並列抽出する

`mslearn search` / `code-search` の結果ファイルを、1件ずつ Read する代わりに `aim --parallel` で並列にAI抽出し、関連する内容だけを報告させる手順。

前提: `aim` コマンドが PATH 上で使え、`OPENROUTER_API_KEY` が設定済み。`aim` の使い方・モデル選択・失敗時の挙動は `aim-cli` スキル(`tools/_plugin/my-tools/skills/aim-cli/SKILL.md`)を参照する。

## 使うとき・使わないとき

判断は必ず `index.md` を Read した後に行う(mslearn 実行直後に返るのは `index.md` のパスのみで、集計値は返らない)。

| 状況                                                                                        | やること                          |
| ------------------------------------------------------------------------------------------- | --------------------------------- |
| 結果が1〜2件で、内容もすぐ読める規模                                                        | そのまま Read(この手順は使わない) |
| index.md でタイトルから選んだファイルが小さい(文字数が少ない)                               | そのまま個別に Read               |
| 件数が多くタイトルだけでは関連性を判断しづらい(目安5件以上)、複数クエリ分をまとめて捌きたい | この手順で全件投入                |
| index.md で選んだファイルの中に文字数が大きいものが複数ある                                 | この手順で選んだ分だけ投入        |
| 1ファイルだけを抽出したい                                                                   | `aim-cli` を直接使う              |
| すでに対象URLが分かっていて全文フェッチだけしたい                                           | `mslearn fetch` をそのまま使う    |

「大きい」の閾値は会話の残りコンテキスト量や個別ファイルの内容次第で変わるため固定値はなく、index.md に付記された各ファイルの文字数を見て都度判断する。

## 手順

```markdown
1. index.md を Read し、結果ファイルへの相対リンク一覧(タイトル・各件の文字数付き)から
   aim に渡す対象を決める(上表。フォルダ直下 = 公式ドキュメント、qa/ 配下 = Microsoft Q&A)

2. 元の質問/知りたいことを1本の「抽出プロンプト」に言語化する(下記)。ファイルごとに
   指示を変える必要は通常ないので、同じ抽出文を各 `--prompt` に繰り返す。ファイル名や
   個々のタイトルはプロンプトに埋め込まない

3. 選んだファイルがおおよそ5件以上ある場合のみ、本実行の前に1件だけを
   `aim --prompt "<抽出プロンプト> @<1件のパス>"` で投げ、エラーなく応答が返ることを
   確認する(モデル側の問題を全件投入前に切り分けるため)。3〜4件規模ならスモークを
   省略して手順4へ進む（1件テスト+本番で実質+1回になり、損失が同じ）

4. 選んだ結果ファイルパスを、ファイルごとに1つの `--prompt` として"まとめて1回" aim に渡す
   aim --parallel --jobs <並列数> --prompt "<抽出プロンプト> @<folder>/0001.md" "<抽出プロンプト> @<folder>/0002.md" ...
   → ファイルごとの応答が返る。Claude 自身が個別ファイルを Read する必要はない

5. 「関連なし」以外の項目だけをユーザーへの回答に統合する。抽出プロンプトで
   「URL:/Link: 行があれば転記して」と指示しておけば、出典URLも追加の Read なしで拾える

6. 抜粋だけでは情報不足な場合だけ、該当ページを mslearn fetch <URL> でフルページ取得し、
   必要なら同じ要領で aim(1ファイルのみでも可)に該当箇所を抽出させる
```

## 抽出プロンプトの作り方

「何を探しているか」をファイル非依存の形で言語化し、指示と対象 `@path` を1プロンプトにまとめて、ファイルの数だけ並べる。

例: ユーザーの質問が「Azure Functions の Python v2 モデルでタイムアウトを変更する方法」の場合

```text
以下はMicrosoft公式ドキュメントの検索結果の抜粋です。
「Azure Functions の Python v2 プログラミングモデルでタイムアウト時間を変更する方法」
に関連する記述があれば、該当箇所を日本語で簡潔に抜き出してください。
冒頭付近の `URL:` または `Link:` 行があれば、それも回答の末尾にそのまま転記してください。
関連する記述が無ければ、他には何も書かず「関連なし」とだけ答えてください。
```

- ❌ 単に「要約してください」だけだと、無関係な結果まで律儀に要約されてフィルタリングにならない。**「関連が無ければ関連なしとだけ答える」を必ず明示する**
- 抜粋が「詳しくは...を参照」のように途中で切れている兆候を拾いたい場合は、「情報が不十分そうなら『要フルページ取得』と付記して」も足すと、手順6に進むべきファイルを aim の応答だけから判断できる
- `code-search` の結果に対しては「探しているコードパターン/実装したい処理」を軸に同様のプロンプトを組み立てる

## 並列数(`--jobs`)の目安

- `search` 結果は既定で最大10件前後(docs+qa を合わせるとさらに増える)。既定 `--jobs 4` でも十分速いが、件数が多い/急ぎなら `--jobs 8`〜`10`(上限)まで上げてよい。`--jobs` は `--parallel` 専用
- 複数クエリの結果フォルダをまたいで一括処理したい場合も、全ファイルを1回の `aim --parallel` に並べれば同様に並列化される
- `--jobs` を上げても速くなるのは AI 呼び出しが正常に進む場合のみ。件数がおおよそ5件以上のときだけ手順3のスモークテストで切り分け、少数なら本実行の失敗を見て `--model` を切り替える

## 注意点

- `aim --parallel` はステートレスで永続化しない。同じ検索をやり直す場合は都度呼び直す(mslearn 側の結果ファイル自体はフォルダに残るため再利用できる)
- 個別ファイルの読み込み失敗・AI呼び出し失敗は、そのプロンプトだけ失敗として記録され他ファイルの処理は継続する。失敗したファイルは `mslearn fetch` など代替手段で個別に読む
- **全ファイルが同一のエラーメッセージで失敗した場合は、モデル/API側の問題を疑う**(例: 既定の無料枠モデルが提供停止で全滅する)。この場合は手順6の個別フォールバックに進んでも無意味なので、`--model` に別のモデル略記(`aim --list-models` 参照)を明示して全件を再実行する
