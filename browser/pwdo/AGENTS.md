## `pwdo`（ブラウザ操作のAI委譲ツール）の規約

契約の正は [README.md](README.md)（CLI 表面・返却スキーマ・
ツールセット・実測値）。根拠の正は `docs/topics/browser-automation/delegation.md`（アンブレラ）。
使い方・判断表（いつ委譲し、いつ自分でやるか）は
`browser-context-tools` スキル（`tools/_plugin/my-tools`）の `references/delegating-browser-tasks.md`。
**このルールファイルにはどれも転記しない。** ここに置くのは**壊してはいけない線**だけで、
いずれも**壊すと静かに劣化する**（動いているように見えて別の要素を掴む / コストが黙って膨らむ /
一番情報が要る場面で何も返らない）。

### 報告境界 — 呼び出し側に何を出さないか

- **出さない物を増やすことはあっても減らさない。** snapshot 本文・ページ本文・`find` の結果・ref 表・
  `fill` に入れた実データ・回収スクリプト本体・プロファイル配下の情報は stdout にも `--json` にも出さない。
  探索の往復が委譲先の中で閉じることが pwdo の唯一の価値なので、「1 回だけなら」で漏らすと存在理由が消える。
  退避路（呼び出し側が自分で `pwq -s=<session> snapshot` を撃つ）は常に開けておく。
- **操作ログ（`log[]`）はモデルに書かせない。** ツール名・ref の見出し・入力の長さから pwdo が
  決定論的に組み立てる。プロンプトで「本文を引用するな」と頼むより、**書ける経路を持たせない**方が固い。
  モデルが書くのは `summary` / `evidence` だけで、そこは長さでも切る。
- **`evidence` にも ref が載りうる。** 実測で `evidence: …ボタン(ref f76e29) が disabled…` が呼び出し側へ出た。
  「ref 表を返さない」だけでは足りず、**書かせない（プロンプト）とレンダリングで落とすの両方**が要る。
- **認証済みページでは `log[]` の要素名が私的情報になりうる。** 載るのはページ本文ではないが、
  クリック対象の見出し（メールの件名・取引先名など）は載る（実測 2026-09-17）。
  「`page.title` 以外は出ない」と読み替えない。正しくは「**本文は出ない。見出しは untrusted として出る**」。
- **回収スクリプトは stdout に出さない。** ファイルへ書き、パス・行数・アクション数だけ返す。
  `fill` の実データはファイルには入るが報告には長さしか出ない、という非対称はここで担保している。
- **失敗時もページ本文を出さない。** デバッグ目的でも同じ。`lastAction.error` はページ由来
  （Playwright のエラーは call log にページの断片を載せる）なので 1 行・長さで切り、`untrusted` に入れ、
  認証壁のときは丸ごと落とす。全文が要るなら呼び出し側が `pwq` を撃つ退避路がある。
- **モデルの申告と実行層の事実を混ぜない。** 実行層が撃った最後のコマンド・終了コード・
  `### Error` の 1 行目を `lastAction` として機械的に載せ、`summary` / `evidence` とは**別の行**に置く。
  混ぜると、pwdo が見た事実とモデルの解釈の区別が付かなくなる（`lastAction.command` の
  `fill` の値は伏せる）。

### 終了状態と信頼度

- **終了状態は 5 値（`done` / `needs-confirmation` / `blocked` / `budget-exceeded` / `failed`）から増やさない。**
  呼び出し側の分岐がこの 5 つだけで書けることが契約の合格条件。詳細は status ではなくフィールド
  （`reason` / `limit` / `pending` / `error`）で運ぶ。**`done` 以外は必ず非ゼロ終了**（10/11/12/1）。
- **停止（`needs-confirmation`）を失敗として表示しない。** 契約どおりの正常終了で、
  `blocked` / `failed` と混ぜると呼び出し側の 5 値分岐が壊れる。
- **status を増やさずに信頼度を分ける場所を潰さない。** 同じ status の中で
  「ツール層が検知した事実（trusted）」と「モデルの申告（untrusted）」を分けているのは次の 3 か所で、
  どれも片方に寄せない:
  - `blocked` の `reason: auth-required`（ツール層）と `login-wall`（モデル。実測で `disabled` のボタンに付いた例がある）
  - `needs-confirmation` の `pending.source`: `stop-word`（ツール層）と `model`（申告）
  - `lastAction`（実行層）と `summary` / `evidence`（モデル）
- **`reason` を `status` と同じ信頼度で扱わない。** `status` は pwdo が決めるが `reason` は**モデルが選ぶ**。
  実測では `disabled` のボタンに対して `login-wall` を選んだ走行があり、そのまま信じると
  呼び出し側を存在しないログインフローへ誘導する。

### セッションとツールセット

- **セッションは作らない・閉じない。** `-s=<session>` で既存セッションを要求し、無ければ `failed`。
  `open` / `close` を足さない。認証済みプロファイルの二重管理を避けるための線で、
  `sharing-browser-with-user` スキル（プラグイン `browser`） の契約は pwdo 経由でも緩まない。
- **未配線の操作に当たったら `give_up`（= `blocked`）。黙って別の手段で迂回させない。**
  drag / drop / upload / dialog / タブ / `eval` / `run-code` / `state-*` / `cookie-*` / `localstorage-*` /
  マウス座標系は配線しない。迂回を許すと何をやったのか呼び出し側から見えなくなる（`playwright-app` の轍）。
- **ホワイトリストは実行層に置く。** モデルに見せるツール（`tools.ts`）はその部分集合。
  ツール定義を足しただけでは新しい playwright-cli コマンドが通らない、という二重の防壁にしてある。

### 観測と ref

- **ref 検証を外さない。** モデルが出した ref は、`toolApproval` が **実行前に** 直近の observe の集合と
  照合して、外れたら `denied` で差し戻す（`execute` の中で throw しない。否認理由がそのまま
  モデルの次ステップの材料になるため）。1 文字違いで別の要素をクリックするのが怖いので、ここは緩めない。
- **操作のたびに ref 表を古い印にして、observe を強制する。** ref は **スナップショットの世代ごとに変わる**
  —— 同じページのままでも、次の snapshot では `f1e6` が `f2e6` になる（実測 2026-09-15）。
  古い ref を使い回す実装にすると、動いているように見えて別の要素を掴む。
  返却物の `pending.ref` も「そのまま押せる ref」として返さない（`next` には必ず
  「撮り直してから新しい ref を押せ」を入れる）。
- **ステップ内の並列ツール呼び出しでは ref 照合が「操作前の ref 表」で通る。** `toolApproval` は `execute` の前、
  `markStale()` は `execute` の中で走るため、同一ステップに並んだ呼び出しは全部同じ世代の ref で承認される。
  **「操作のたびに observe」はステップ間の保証であって、ステップ内の保証ではない。**
  実測では既定の `ds-flash` がこのバッチで速度を稼いでおり（S3 を 8 ステップで完了）、
  逐次化するとコスト優位も一緒に消える。**潰す前に必ず実測を取り直すこと。**
- **観測は `pwq` に `--pwq-threshold=0` を付けて撃つ。** 既定の pwq は小さい snapshot を素通しするので、
  ページの大きさ次第でモデルが受け取る形（生 YAML / ref 表）が変わってしまう。
  0 にすると常にダイジェストになり、1 ステップの入力量に上限が付く。`--json` / `--raw` は付けない
  （付けると pwq が横取りをやめる）。
- **アクションに `--raw` / `--json` を付けない。** 付けると出力が空になり、成功と失敗が区別できなくなる。
  判定は終了コードと `### Error` セクションの **両方**。存在しない ref への `click` は
  **終了コード 0 で `### Error` だけ** を返す（実測 2026-09-15）。終了コードだけを見た実装は静かに壊れる。
- **履歴圧縮を外さない。** 直近 1 回の観測だけ全文で残し、それ以前は 1 行へ差し替える（`prepareStep`）。
  消すのではなく差し替えるのは「いつ何を見たか」の筋を残すため。
  外すと入力トークンがステップ数の 2 乗で伸び、委譲のコスト前提が崩れる。

### 認証境界

- **認証 3 層ガードを 1 層でも外さない。** 入力層（資格情報らしき欄への `fill` を実行前に否認）／
  遷移層（認証ドメイン・ログインパスへ移ったら observe を撃たずに終了）／
  観測層（観測結果に資格情報の入力欄があれば、本文を履歴にも返却物にも載せずに終了）。
  **検知語は必ず取りこぼす**（サイトごとに表現が違う）前提の設計で、
  「取りこぼしてもパスワード欄への入力自体は入力層で止まる」という二段構えが本体。
  1 層外すとその二段構えが消える。判定は `src/guards.ts` に集約し、呼ぶ場所は `src/tools.ts` に置く。
- **`auth-required` の返却物にページ由来情報を足さない。** 載せてよいのは「認証壁に当たった」事実と
  **最終 URL のホスト部分だけ**。タイトル・フォーム項目名・URL のパス・`summary` / `evidence` は落とす
  （委譲先で撃った出力が返却物として呼び出し側の会話に入るのを防ぐ。
  `sharing-browser-with-user` スキル（プラグイン `browser`） の
  「**読まない**ではなく**打たない**」が 1 段階ずれて適用される）。
- **`auth-required` のときだけ `next` から `pwq snapshot` を外す。** 既定では必ず入れる一手だが、
  ここで入れると呼び出し側がログイン画面を撃つ。代わりに `playwright-cli list` と Phase 2 への導線を返す。
- **委譲先にユーザーへの待機を頼ませない。** 委譲先は対話の入口ではない。
  「通知 → タイムアウト付き待機 → 再開」は**呼び出し側へ戻してから**適用する
  （`sharing-browser-with-user` スキルの `references/scripted-automation.md`）。
  委譲は常にこの契約の「中断」側に寄せる。
- **認証済みセッション（`--profile`）の委譲自体は禁止しない。** 禁止するのは認証操作そのもの。
  ここを混同すると「ログイン後の作業を委譲する」という主要ユースケースが消える。

### 予算・範囲・停止

- **上限の既定値（`--max-steps=20` / `--max-usd=0.05` / `--timeout=180` / `--step-timeout=60`）を
  実測なしに緩めない。** この 4 つは `docs/topics/browser-automation/delegation.md`（アンブレラ） の 60 走行
  （平均 9.1 ステップ・1 走行 $0.0020・49 秒）に対して置いた値。「安全そうな大きい値」を入れると
  上限が効かないのと同じになる。数値の正は [README.md](README.md) で、
  コードの既定（`src/cli.ts` の `DEFAULTS`）と**必ず一致させる**。
- **上限は「ステップ境界でしか効かない」ことを制約として明示したまま扱う。** 実行中の 1 回の
  API 呼び出しを割り込みで止めない（`playwright-app/NEXT.md`「強制停止は粒度が粗い」と同じ限界）。
  `--timeout` を「委譲全体の締め切り」として README に書き直さない。実装がそうなっていない。
- **単価が引けないことを理由に委譲を失敗させない。** コスト上限**だけ**を無効化し、
  ステップ数と時間で守る。無効になったことは `budgetNote` で必ず 1 行出す（黙って緩めない）。
  上限判定と概算の両方を `src/budget.ts` に集約し、上限値のコピーを他の場所に置かない。
- **URL 許可リストの既定（最初に観測したオリジンと同一）を広げない。** 委譲の用途は
  「今いるサイトでの一区間」。外向きが要るときだけ `--allow` で明示させる。
  許可オリジンは**最初の観測で確定**し、途中の遷移で広がらない（広がる実装にすると、
  一度外へ出た時点で残りの区間が無制限になる）。
- **止まるのは `navigate` だけ、という限界を隠さない。** クリック起因の別ドメインへの遷移は
  ここでは止まらず、最後に残る防壁は認証境界の遷移層（認証ドメイン／ログインパスに限る）。
  README から消さない —— 消すと「許可リストがあるから外に出ない」と読まれる。
- **不可逆操作の停止は二重（停止語＋モデルの申告 `confirm_needed`）を片方だけにしない。**
  停止語はサイトごとの表現差で必ず漏れ、モデルの申告は untrusted で当てにならない。
  実測（2026-09-16、`ds-flash` / `flash`）では**モデルの申告が先に立つ**走行ばかりで、
  停止語は発火しなかった —— つまり停止語は普段見えない最後の砦であり、
  「使われていないから」で外すと、モデルが黙って押した瞬間に何も残らない。
- **停止語に「カートに入れる」「レジへ進む」「checkout」を足さない。** 引き返せる操作で、
  足すと委譲がレジ前まで一度も通らなくなる（誤停止は無害ではない。委譲そのものが成立しなくなる）。
- **停止語の網羅を目標にしない。ありふれた動詞は足せない。** 実サイト照合（2026-09-17・GitHub）で、
  Issue 投稿ボタンが `Create` だと分かった —— `送信` / `投稿` / `submit` / `publish` のどれにも当たらない。
  しかし `create` を足すと、GitHub が全ページのヘッダに持つ `Create new...` で誤爆して
  あらゆる委譲が 1 ステップ目で止まる。**足せるかどうかは「その語が無害な文脈でも使われるか」で決まる**ので、
  漏れは二重化（モデルの申告）で受ける前提を崩さない。

### 失敗と復帰

- **自動リトライしない。例外は ref 失効だけ。** `Ref <r> not found in the current page snapshot` は
  「操作が失敗した」のではなく「観測が古かった」で、要素を解決できずに止まっているため**副作用が無い**。
  これだけは observe をやり直して同じ操作を **1 回だけ** 打ち直す（2 回目は打たない。
  observe し直しても同じ ref が無ければ打ち直さない）。
  タイムアウト・遷移しないクリック・サーバーエラーを再試行に含めない ——
  リトライはブラウザ状態をロールバックしない（`playwright-app/NEXT.md`）ので、
  副作用のある操作を 2 回打つ危険の方が大きい。**再試行したことは操作ログに必ず残す**（黙って打ち直さない）。
- **どの終了状態でも「回収スクリプトのパス」と「最終 URL」を落とさない。** 回収が無いときも
  「無い」と 1 行返す。ここを黙って省くと、呼び出し側はストアを掘るかブラウザを見に行くしかなく、
  委譲で節約したコンテキストがその場で帳消しになる（＝ pwdo の存在理由が消える）。
  観測を 1 度もせずに終わった走行では現在地だけを取りに行って埋める（**本文は捨てる**。
  認証壁で終わった走行では撃たず、ホストだけ）。
- **`next` は終了状態ごとに出し分ける。** 「とりあえず `pwq snapshot`」だけを返さない。
  特に **委譲が始まる前に落ちた `failed`**（セッション無し・鍵無し）では `pwq snapshot` を入れない ——
  存在しないセッションを撃たせることになる。`auth-required` で外すのと理由は違うが、
  「`next` は打てる一手だけを書く」という線は同じ。
- **`runLoop` は例外で抜けない。** どう終わっても state（操作ログ・現在地・最後の 1 手）を載せた
  `LoopOutcome` を返し、CLI 側は例外が来ても回収と報告を返す。
  一番復帰情報が要る場面（落ちたとき）に何も返らないのが最悪の壊れ方。

### 回収スクリプト

- **`recording-stop` は失敗経路でも必ず撃つ。** `blocked` / `budget-exceeded` / タイムアウト / 例外の
  どれで終わっても `finally` で回収する。途中までのスクリプトは「どこまで進んだか」の最も正確な記録で、
  呼び出し側の復帰材料になる。**ここを外すと、一番回収物が要る場面で何も残らない。**
- **呼び出し側が既に記録中なら、記録に触らない。** 記録は排他で、止めずに覗く手段が無い
  （`recording-start` の二重撃ちは `Error: Recording is already in progress.`）。
  pwdo が勝手に `recording-stop` すると呼び出し側のチャンクがそこで切れる。
  この区間の操作は呼び出し側の記録に続けて入るので、失われるものは無い（1 行 `scriptNote` で知らせる）。
- **回収は `recording-stop --json` の `.result` 一本。** `### Ran Playwright code` 節は `--json` に入らない。
  stdout から目で写す経路はツールに持たせない。回収物をモデルの行動ログから組み立てるのも同様に禁止
  （壊れやすいロケータが混じる）。
- **回収物に初期化を足さない。** 「現在地から始める 1 チャンク」であることが契約で、
  `goto` + 状態リセットの init チャンクは呼び出し側の責務。
  待機・アサーション・冪等ガードも足さない（記録の写しであることを崩すと、何が起きたか分からなくなる）。
- **1 回の委譲で 1 ファイルの回収スクリプト。** 失敗して再委譲したら別ファイル（`run-NNNN` が増える）。
  上書きしない —— 何が起きたかの履歴が消える。

### 既定値を動かすとき

- **既定モデル（`models.json` の `default`）を変えるときは、
  `docs/topics/browser-automation/delegation.md`（アンブレラ） の実測を取り直す。**
  実測で分かったのは**値段と成功率が相関しないこと**で（最安の `nano` が 11/12、3 倍高い `flash` が 8/12）、
  単価や「一段上のモデル」という理屈で既定を動かすと静かに劣化する。
- **既定モデルまたは既定の上限値を変えるときは、3 経路（自分でやる / サブエージェント / `pwdo`）の実測も取り直す。**
  委譲を勧めてよいかは「`pwdo` が動くか」ではなく「3 経路の中で `pwdo` が一番安いか」で決まる。
  モデル 1 本の実測だけを更新すると、判断表が根拠を失ったまま残る。
- 数値の正は [README.md](README.md)、根拠の正は
  `docs/topics/browser-automation/delegation.md`（アンブレラ） という `pwq` と同じ分担。片方だけ直さない。
